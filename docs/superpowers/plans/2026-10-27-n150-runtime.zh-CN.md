# N150资源优化计划

[English](2026-10-27-n150-runtime.md) | [简体中文](2026-10-27-n150-runtime.zh-CN.md) | [日本語](2026-10-27-n150-runtime.ja.md)

本文件记录2026-10-27的实施决策与当时验证范围。

目标是在 Intel N150 + 8 GB、Linux/Docker 上减少 CPU 工作量、内存和请求延迟，保持当前 FP32 模型、预处理及阈值。

当时 SSH 无法连接目标机，本机 ARM 测量仅作辅助证据，目标性能结论等待实机基准。

## 设计

- 保持模型资源、人脸检测分辨率、对齐、特征顺序和阈值。量化、半精度、骨干替换与其他执行提供器另行研究。
- 添加兼容旧配置的布尔选项 `runtime.allow_spinning` 与 `runtime.enable_cpu_mem_arena`，默认 true，三个会话一致应用。
- 每种线程、调度、自旋和内存池配置使用新进程，包括当前并行双线程配置。模型加载后分别测量预热请求的墙钟、CPU、峰值RSS及短暂空闲CPU。
- 基准使用显式合成裁剪或用户提供的对齐裁剪。加载检测器以体现真实进程内存，计时路径明确为对齐裁剪分类，报告包含聚合一致性与性能。
- 本地测量后添加 N150 配置和 Compose 覆盖文件，标注为目标机验证起点，并保持一个 Uvicorn worker。
- 按显式构建清单将目标测量工具加入 Docker 镜像，本地部署包包含 N150 配置、覆盖文件和文档。GitHub Release 仅交付模型。

## 决策记录

用户目标是 Linux + Docker、N150 + 8 GB，当时网络无法访问。精度保持通过模型计算与历史数据回归核对，后续输入和未验证硬件需要单独检查。

原图核查发现检测器线程1与2的关键点差异最多0.000183像素，对齐后概率差异0.000149。受控诊断确认 detector=2 恢复完全一致。添加独立 `detector_intra_op_threads`，None 继承原行为。N150识别线程1、检测线程2、自旋false、内存池true。

最终固定检测器的本机基准为 current parallel2/on，墙钟53.23 ms、CPU192.09 ms、峰值932.77 MiB，efficient parallel1/off为57.05 ms、101.62 ms、928.95 MiB，latency parallel2/off为51.89 ms、181.47 ms、931.28 MiB。测量平台是 ARM，已加载但未执行检测器，指标针对裁剪分类。

两个最终候选在1,051张留出裁剪上的特征、概率、Top-5、阈值处置均一致，12张原图14张脸的完整结果一致。原生 systemd 文件完成静态检查，Linux启动尚待验证。独立审查补清内存池测量表述后通过。本机包 `/tmp/seiyuu-n150-deployment-final-20261027` 核实21个清单文件，包含模型、配置和文档。原生运行还需要仓库代码与依赖。
