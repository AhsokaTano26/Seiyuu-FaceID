# HTTP API実装計画

[English](2026-10-21-http-api.md) | [简体中文](2026-10-21-http-api.zh-CN.md) | [日本語](2026-10-21-http-api.ja.md)

2026-10-21の計画を記録します。当時は superpowers:executing-plans に従いタスクごとに実行しました。

目的はHTTPで画像をアップロードし、構造化した顔検出と人物分類の結果を受け取れるようにすることです。

FastAPIファクトリーがlifespanでFaceIdEngineを一度読み込みます。アップロード検証と画像復号を分離し、HTTPスキーマを明示し、スレッドプールで推論を直列実行します。既存pipelineを使用し、学習、重み、ウェブ動作、既存の未コミット作業を保持します。

FastAPI、Uvicorn、python-multipart、Pillow、テスト用httpxを使用します。ユーザーは実装前にAPI文書を要求し、`docs/API.md` に記録しました。

## 全体の制約

- API extraは任意です。既存Python/CLI/webはそれぞれの依存で動作します。
- 未コミット作業を保持し、現在の作業ディレクトリで実装します。当段階はGit commitやworktree移行を行わない条件でした。
- JPEG/PNG/WebP、1ファイル10 MiB、要求81 MiB、20,000,000画素、一括1–8枚を上限とします。
- top_kとprobability_thresholdの既定は設定値で、当時は5と0.95です。
- エラー応答からモデル・キー・パスの詳細を保護します。推論引数は要求単位で渡し、共有設定を固定します。

## レビュー重点

- Content-Lengthなしの途中アップロードでも総量超過は共通413を返します。
- EXIF後の座標を整合させ、巨大画像を全復号前に拒否します。
- 混在バッチは順序を保持して正常項目を継続し、モデル失敗はサーバーエラーとします。
- モデル不足は診断可能な起動失敗、500は内部パスを保護し、推論中も健康確認を応答します。
- 並行要求によるtop_k/しきい値変更と、並列推論によるメモリ蓄積を防ぎます。
