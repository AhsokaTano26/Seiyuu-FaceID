# 分类器优化实施计划

[English](2026-10-27-classifier-optimization.md) | [简体中文](2026-10-27-classifier-optimization.zh-CN.md) | [日本語](2026-10-27-classifier-optimization.ja.md)

本文件记录2026-10-27的实施决策与验证结果。

目标是通过可复现的开发集模型选择和实测运行时调整改善分类准确率与速度。

架构是在冻结的 AdaFace/R50 特征上比较可移植的逻辑回归分类头。开发集按来源隔离，只有一个组件的身份仅用于训练，观察历史测试预测前先锁定胜出配置，另行导出兼容当前运行时的 NumPy 分类头。使用持久执行器并行运行两个冻结骨干，固定特征顺序并保留顺序执行选项。

技术栈沿用 NumPy 与 scikit-learn 环境。

## 设计与约束

- 优先优化 Top-1，其次为合并后有真值类别的 Macro-F1，再次为对数损失，最终以固定候选顺序打破平局。
- 开发集为原训练与验证合计4,064张。1,051张历史测试样本与预处理、候选选择及拟合隔离。
- 按来源组、来源校验值、裁剪校验值、样本ID和可选写真集组连接样本。发现跨开发/测试池或身份冲突的组件时拒绝继续实验。
- 只有一个组件的身份固定进入每折训练，并从验证统计排除。每折训练均包含全部身份。
- 比较标准化逻辑回归的正则化、类别权重、标准化后的特征块权重、无标准化逻辑回归、来源组件等权方案。这些方案可导出为现有仿射 softmax 分类头，非线性方案留作后续独立实验。
- 将协议、折索引、候选指标、选定配置、最终分类头、留出比较与来源写入新的 Git 忽略 `data/experiments/` 目录。部署模型包单独管理，私有数据保持本地。
- 历史测试曾参与模型选择，结果延续探索性口径。未知身份准确率需要带标签的未知样本。

## 进展

复现基线 Top-1 为1,035/1,051，0.95阈值接受1,011张，其中4张错误。开发池存在2个只有一个组件的身份，开发/测试间重复组件交集为0。

用户明确准确率和速度都重要。固定搜索选中标准化逻辑回归 C=0.1、类别平衡、AdaFace权重0.75。选择用 OOF 正确数3,977→3,986，第二种子 OOF 为3,981→3,988，历史测试为1,035→1,033。因此继续采用部署分类头。历史测试与第二个开发划分分别保持探索性、复用样本的口径。

本机配对基准在相同 intra-op=2 下，用16个开发来源组×3轮测得顺序特征平均78.39 ms、并行54.22 ms，特征与概率完全一致。启用实测并行模式，并在完成前核对真实运行时的全部留出数据。

实际并行运行时核对全部1,051张历史裁剪，顺序与并行的特征、概率、Top-1和阈值处置均一致。平均特征延迟77.61→52.12 ms（−32.8%），P95为79.35→55.40 ms。独立审阅未发现重要问题，完整131项测试通过，部署头校验值相同。[实测报告](../../CLASSIFIER_OPTIMIZATION.zh-CN.md)记录详情。
