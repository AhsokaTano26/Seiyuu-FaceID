# N150 resource optimization plan

[English](2026-10-27-n150-runtime.md) | [简体中文](2026-10-27-n150-runtime.zh-CN.md) | [日本語](2026-10-27-n150-runtime.ja.md)

This file records the implementation decisions and verification scope of 2026-10-27.

The goal was to reduce CPU work, memory and request latency for Linux/Docker on Intel N150 + 8 GB while retaining the current FP32 models, preprocessing and decision thresholds.

At that time, the target machine is currently unreachable by SSH. Local ARM measurements are supporting evidence only, never estimates of N150 latency. All target performance conclusions await its own benchmark.

## Design

- Keep model assets, face detection resolution, alignment, feature order and threshold unchanged. Quantization, half precision, different backbones and different execution providers are outside this accuracy-preserving runtime change.
- Add backward-compatible bool options `runtime.allow_spinning` and `runtime.enable_cpu_mem_arena`, defaulting to existing ORT behavior (`true`). Apply consistently to all three sessions.
- Compare fixed thread/scheduling/spinning/arena profiles in fresh processes, including the current parallel 2-thread configuration. Measure warm request wall time, CPU time, peak RSS and short post-request idle CPU separately from model load.
- Benchmark uses explicit synthetic crops or user-supplied aligned crops, never needs training data on the server. Load the detector as well for realistic process memory, while clearly labeling the timed path as aligned-crop classification. Reports contain aggregate parity and performance, not photos, embeddings or identities.
- Add an N150 deployment profile and Compose override after local measurements. Keep its settings identified as a starting point for target verification, not a claimed target winner. Retain one Uvicorn worker.
- Add a target benchmark script to the Docker image using the existing explicit build allowlist. Extend the local deployment bundle to carry the N150 config, override and documentation. This is not a GitHub Release attachment.

## Decision record

The user targeted Linux + Docker, N150 + 8 GB, unreachable from the current network. Accuracy preservation means unchanged model computation plus regression against the existing historical data. No guarantee is claimed for every future image or for target hardware not yet tested.

Original-image verification found detector thread count 1 vs 2 changed landmarks by up to 0.000183 pixels, changing aligned-image probabilities by 0.000149. A controlled diagnostic confirmed preserving detector=2 restores exact outputs. Added independent `detector_intra_op_threads` override (None inherits existing behavior). N150 recognition threads=1, detector threads=2, spinning=false, arena=true.

The final local fixed-detector benchmark measured current parallel2/on mean wall53.23ms CPU192.09ms peak932.77MiB. Efficient parallel1/off wall57.05ms CPU101.62ms peak928.95MiB. Latency parallel2/off wall51.89ms CPU181.47ms peak931.28MiB. These ARM measurements time crop classification with the detector loaded in process.

Both final candidates preserve every feature, probability, Top-5 and threshold decision on 1,051 holdout crops and exact full results on 12 originals/14 faces. Native systemd files were statically checked. Linux startup remains untested. Independent review clean after clarifying an arena-measurement sentence. Final local bundle `/tmp/seiyuu-n150-deployment-final-20261027` verified 21 allowlisted files (models/config/docs only. Native operation additionally requires repository code and dependencies).
