# HTTP API Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让调用方通过 HTTP 上传图片并获得结构化人脸检测与身份识别结果。

**Architecture:** FastAPI app factory 在 lifespan 中加载一次 FaceIdEngine；上传验证和
图片解码独立，HTTP schema 显式定义，推理在线程池中串行执行。复用现有 pipeline，
不改动训练、模型权重、网页行为或现有未提交工作。

**Tech Stack:** FastAPI、Uvicorn、python-multipart、Pillow、httpx（测试）。

**Spec:** `docs/API.md`（按用户要求先写 API 文档，再补全实现）。

## Global Constraints

- API extra 可选；现有 Python/CLI/web 不依赖 API extra。
- 保留现有所有未提交变更，在当前工作目录实现，不执行 Git 提交或迁移工作树。
- JPEG/PNG/WebP；单文件 10 MiB，整请求 81 MiB，20,000,000 像素，批量 1–8 张。
- 默认 top_k=配置值（当前 5）、probability_threshold=配置值（当前 0.95）。
- model/key/path 不进入异常响应；推理参数按请求传递，禁止修改共享配置。

## Review Focus

- 上传中途越过总请求限制：无 Content-Length 也应得到统一 HTTP 413。
- 方向与像素限制：EXIF 旋转后坐标自洽，超大图片在完整解码前被拒绝。
- 批量混合输入：单项失败保留顺序，其他合法图片继续，模型错误不被当作坏图片。
- 模型缺失与异常：启动失败可定位；HTTP 500 不泄露内部路径；健康检查不被推理阻塞。
- 并发及请求参数：共享模型不会被 top_k/阈值改变，单进程推理不会并行堆积内存。
