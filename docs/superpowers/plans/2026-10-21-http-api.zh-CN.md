# HTTP API实施计划

[English](2026-10-21-http-api.md) | [简体中文](2026-10-21-http-api.zh-CN.md) | [日本語](2026-10-21-http-api.ja.md)

> 本文件记录2026-10-21的实施计划。当时按 superpowers:executing-plans 逐项执行。

目标是 让调用方通过 HTTP 上传图片并获得结构化人脸检测与身份识别结果。

架构为 FastAPI app factory 在 lifespan 中加载一次 FaceIdEngine，上传验证和
图片解码独立，HTTP schema 显式定义，推理在线程池中串行执行。复用现有 pipeline，
不改动训练、模型权重、网页行为或现有未提交工作。

技术栈为 FastAPI、Uvicorn、python-multipart、Pillow、httpx（测试）。

接口规范见 `docs/API.md`（按用户要求先写 API 文档，再补全实现）。

## 全局约束

- API extra 可选，现有 Python/CLI/web 不依赖 API extra。
- 保留现有所有未提交变更，在当前工作目录实现，不执行 Git 提交或迁移工作树。
- JPEG/PNG/WebP，单文件 10 MiB，整请求 81 MiB，20,000,000 像素，批量 1–8 张。
- 默认 top_k=配置值（当前 5）、probability_threshold=配置值（当前 0.95）。
- model/key/path 不进入异常响应，推理参数按请求传递，禁止修改共享配置。

## 审阅重点

- 上传中途越过总请求限制时，无 Content-Length 也应得到统一 HTTP 413。
- 对于方向与像素限制，EXIF 旋转后坐标自洽，超大图片在完整解码前被拒绝。
- 对于批量混合输入，单项失败保留顺序，其他合法图片继续，模型错误不被当作坏图片。
- 遇到模型缺失与异常时，启动失败可定位，HTTP 500 不泄露内部路径，健康检查不被推理阻塞。
- 对于并发及请求参数，共享模型不会被 top_k/阈值改变，单进程推理不会并行堆积内存。
