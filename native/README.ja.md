# C++ 推論 + Go HTTP

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

既存の FP32 モデル向けの実験的な代替実行系です。Go は cgo 経由で同一プロセス内の C++ ライブラリを呼びます。モデル推論、検出、アライメント、分類は C++、HTTP、アップロード検証、認証は Go が担当します。Python はモデル準備と比較だけに使い、提供中には不要です。

[ビルド、検証、デプロイの説明](../docs/NATIVE_CPP_GO.ja.md) を参照してください。認識全体、学習、実行時の設計理由は [技術アーキテクチャガイド](../docs/TECHNICAL_ARCHITECTURE.ja.md) にあります。既存の Python 実行系を参照実装として維持します。

Intel N150 対象機では Linux ビルドと起動、過去のホールドアウト 1,051 枚と元画像 12 枚の一致性、完全な3組の HTTP ベースラインを確認しました。同設定のネイティブ版は確かな高速化を示さず、ピーク RSS が増えました。省 CPU 設定の平均 HTTP 遅延は旧スレッド Python 組より約 37.9% 増えました。範囲、結果、後続の独立実験は [N150 レポート](../docs/N150_BENCHMARK.ja.md) にあります。検証済みの FTZ/DAZ 版は 2026-10-28 に N150 API サービスを置き換えました。長期稼働と負荷の受け入れ確認は残っています。

後の独立 FTZ/DAZ 候補は全件回帰と新規3プロセスの HTTP 測定に合格しました。各プロセスの平均リクエスト時間の中央値は 680.785 ms、過去のホールドアウト Top-1 は 98.48% を維持しました。後続段階の実験で、同時期に交互実行した A/B ではありません。実装は現在のソースに含まれます。対応 Linux x86_64 では出力時の `--flush-denormals` で有効化します。互換性のため既定は無効、Mac ARM は有効化を拒否します。実装、メモリのトレードオフ、検証範囲は [FTZ 実験](../docs/N150_BENCHMARK.ja.md) を参照してください。

[systemd テンプレート](deploy/seiyuu-faceid.service) は単一のネイティブプロセスを実行します。[デプロイガイド](../docs/NATIVE_CPP_GO.ja.md#linux-systemd) は配置、認証情報、起動、復旧を説明します。API を提供し、Python の Swagger とアップロード UI ルートは含みません。
